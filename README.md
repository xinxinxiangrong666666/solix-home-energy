## 这是什么

这是 Anker SOLIX Home Energy Studio 的**独立产品官网原型**，为 Anker 充电储能赛道黑客松构建：

- **一个真实运行的能源调度系统**：浏览器端线性规划（LP）滚动求解电池充放电计划，读取电价、光伏、家庭负荷与备电约束；
- **一个可走进去的 3D 能源孪生场景**：Three.js 室内家庭 + 室外车位一体化场景，家具可拖拽布置，电力链路完整可视；
- **一个会解释的 AI 助手**：每个调度决策都能追问"为什么现在充电/为什么不多充"，回答全部引用可点开的证据 JSON——AI 只组织文字，永不决定功率。

页面参考 Anker SOLIX 官方产品页的内容层级、黑白高对比与橙色行动点风格，不复制官方源码。

## 核心特性

### 3D 能源孪生场景

![白天场景](assets/hero-home_c.jpg)

- Three.js 室内 + 室外一体化场景，真实比例 PBR 家具（织物沙发、橡木皮椅、石材茶几、冰箱、洗衣机、盆栽）与动态添加设备；
- CC BY 4.0 授权的 Tesla Model 3 PBR 模型 + SOLIX V1 风格车充；
- 电力链路完整建模：屋顶微型逆变器 → 家庭配电箱 → 智能电表/CT → Solarbank Max AC（按官方 `670 × 356 × 325 mm` 比例概念建模，非官方 CAD）；
- 选中物体 15° 步进旋转、自由拖拽布置、碰撞检测（阻止穿墙/重叠/穿入产品区），布局保存在浏览器本地；
- 能源全景 / 室内 / 车充 / 产品特写 / 俯视五种视角一键切换，滚轮缩放、空白区拖动旋转。

### 六种天气 × 一整天时间变化

![夜间场景](assets/night-solix-max-v2.jpg)

- 晴朗、多云、雨天、雷暴、降雪、夜间六种场景实时切换；
- 模拟时钟驱动太阳弧线、天空色、室内灯光连续变化；
- 雷暴/降雪联动光伏预测、备电目标上调、车辆充电暂停与 AI 解释话术。

### 真实 LP 优化，不是演示动画

- 浏览器端 6 小时 / 24 时隙滚动 LP：电池与车充共同求解，含演示用 €0.02/kWh 循环成本假设；团队正式目标为 24 小时 / 三站，尚待官方环境验证；
- 智能优化 / 自发自用 / 备电优先 / 手动控制四种策略；
- 7 kWh 模拟电池 SOC 动态演化；光伏、电池、家庭负荷、电网实时功率模拟；
- 最近 120 分钟光伏/负荷曲线；
- 三站合成情景预览：共享同一条模拟电价，各站独立光伏/负荷/SOC，同一 LP 核分别求解；时间线仅展示当前网页真实的 6 小时计划，不冒充正式三站成绩。

### 反事实影子重算 — "为什么不多充？"

点一下"为什么不多充"，网站在**同一组模拟输入**下加约束重新求解，比较完整窗口的含循环成本目标值：

- 差额 ≈ 0 → 说明当前计划已贴近该约束下的成本最优（LP 已选了最省的可行策略）；
- 触及功率上限 → 直接说明上限数值，不拼造数字；
- 无可行解 → 说明是 SOC、备电目标还是出发约束冲突。

### 证据助手 — 数字全部可追溯

- 每次 LP 求解自动记录：输入快照、首格动作、目标值与显式规则（当前标签页环形保留最近 96 条，刷新清空）；
- 追问"为什么充电/为什么不多充/待机会怎样"，回答引用证据编号，可点开原始 JSON；
- **可选云端文字解释**（GLM）：默认本地规则回答；用户了解发送范围后可主动开启云端——LLM 只收到最近一条合成证据 + 问题，只产出解释文本，无任何工具调用能力；
- **两种模式都没有设备控制权限**：这条边界写在页面里，也写在代码里。

## 立即运行

### 在线版（推荐）

直接打开：**https://xinxinxiangrong666666.github.io/solix-home-energy/**

### 本地运行

Three.js 使用 ES Module，请通过本地 HTTP 服务打开，不建议直接双击 `index.html`。核心 Three.js 文件已保存在 `vendor/`，无需 CDN：

```powershell
python -m http.server 4173
# 浏览器访问 http://127.0.0.1:4173/
```

### 启用云端解释（可选）

配置服务端 `ARK_API_KEY` 或 `LLM_API_KEY` 环境变量后：

```powershell
python serve.py 4173
```

- 代理默认仅监听 `127.0.0.1`，key 只存在服务端环境变量，**永远不进入前端代码**；
- 没有可用代理时，页面自动降级为本地解释，其余功能不受影响。

## 技术架构

```
┌──────────────────────────────────────────────────┐
│                  浏览器（全本地）                   │
│                                                    │
│  scene-realistic.js ── Three.js 3D 孪生场景        │
│  energy-lp.js ──────── 24 时隙滚动 LP 求解         │
│  energy-session.js ─── 决策证据环形日志（96 条）    │
│  app.js ────────────── 模拟引擎 / 三站 / UI 状态    │
│  revenue-ledger.js ─── 模拟收益账本                 │
│  energy-agent.js ───── 证据助手（本地规则优先）     │
│  llm-bridge.js ─────── 云端解释开关（可选）         │
└───────────────────────┬──────────────────────────┘
                        │ 仅当用户主动开启云端
                        ▼
               POST /api/chat（本地代理）
                        │ 只转发文字，无工具调用
                        ▼
                  GLM 解释模型
```

- 纯前端静态站点，Three.js 本地化打包（`vendor/`），零 CDN 依赖；
- LP 求解、证据记录、反事实重算全部浏览器端完成；
- 云端链路只是"文字解释"的表达层：证据数字全部来自本地 LP 日志，LLM 不能下发功率、修改约束或访问任何设备。

## 数据与品牌边界

- 页面为**交互产品原型**，不是已上线的 Anker SOLIX 商业服务；
- 所有功率、价格、SOC、成本变化与解释均为**本地模拟**；
- 收益页的模拟 `R = 全量购电基准 − 买电支出 + 卖电收入`，以本页功率与同一条合成买卖电价逐段积分；仅切换到会重置时钟的非夜间新天气时清空账本，刷新页面归零。此 `R` 不是官方同名字段或实际账单；`R_settled` 在无官方结算回执时始终显示"待官方结算"，不从 `R` 猜测；
- 不展示或承诺未经官方环境验证的收益成绩；
- 未接入真实设备、真实 Home Assistant 或外部能源系统；
- 电表/CT、微型逆变器、配电箱和智能插座均为依据示意图重建的概念场景模型；Solarbank Max AC 的光伏经既有逆变器并入家庭交流侧；
- 站点 2/3 使用合成光伏、负荷与 SOC，电价与站点 1 共享；不是官方三站的实际数据或 `saving_settled_percent`；
- Solarbank 与 V1 车充为依据公开产品图和尺寸制作的程序化场景模型；车辆使用单独署名的 CC BY 4.0 第三方模型。

## 进入正式演示前仍需完成

- 在官方 EC2/HA 环境核验三个实体后缀、`third_party_control` 切换、`power_control` 下发及逐站功率读回；此网站不能替代现场闭环；
- 用官方三站合并 `saving_settled_percent` 与设备原生自发自用基线形成真实对照，替换"待官方结算"说明；不得使用浏览器模拟目标值冒充成绩；
- 明确正式环境日志保留期和访问权限，准备故障时可播放的备用演示视频。
